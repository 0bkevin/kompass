# Complete company workflow — implementation contract

Root owns App.tsx, CompanySetup.tsx, routes, types.ts, global CSS, server/index.mjs, db.mjs, existing modules integration and QA. Agents own only their assigned new files. Existing implementation is copied without private data or keys. Brand scope always validated with auth middleware; frontend cache reset/guarded on brand switch. No claims of audience observation from enrollment or public metadata.

## Context module: server/company-context.mjs + tests/company-context.test.mjs

Export createCompanyContextRouter() and inspectCompany(input, options) for tests. Reuse safeFetch, existing DB and authentication. POST /api/context/inspect (requireAuth) input {website?,urls?:string[],text?:string}; returns Inspection {id,inspectedAt,method:'heuristic'|'ai',draft:{name,industry,description,website,market,language,tone,pillars:string[],audience:Segment[]},evidence:ContextEvidence[],warnings:string[]}. ContextEvidence {id,url?,title,excerpt,status:'read'|'linked'|'failed'|'provided',platform,reason?}. Public website HTML/text extraction is bounded, detects login/blocked/unreadable pages; social links without supported provider are linked, never imported. Redact contact details from extracted excerpts. Suggestions labeled inference, not consumers observed. Require website OR URLs OR text. Inspector results cached per authenticated user for 30m; before-brand inspection needs no per-brand AI call. Website no-scheme may be normalized to https.

POST /api/brands/:brandId/context/commit {inspectionId} owner only: consume cached user-owned inspection; save contextImports record including inspection; returns {import:Inspection}. GET /api/brands/:brandId/context returns {imports:Inspection[]}. POST /api/brands/:brandId/context/import owner only: same inputs; inspect and persist, returns Inspection. DELETE /api/brands/:brandId/context/:id owner only. No existing brand fields silently overwritten. Draft fields are submitted via normal brand CRUD after explicit review. Optional apply endpoint unnecessary.

## Insights module: server/audience-insights.mjs + tests/audience-insights.test.mjs

Export createAudienceInsightsRouter(), buildInsights(brand, options), recordTopicObservation(brandId, options). Do not import intelligence.mjs (root calls recordTopicObservation after successful sync; avoid cycle). DB kinds provided by root: contextImports, audienceSignals, outcomes, topicSnapshots.

GET /api/brands/:brandId/insights → Insights {generatedAt,opportunities:Opportunity[],coverage:{references:number,sources:number,activeSources:number,errors:string[],hasHistory:boolean,notes:string[]},signals:AudienceSignal[],learning:{outcomes:Outcome[],summary:string,bySegment:Array<{segmentId:string,name:string,pieces:number,views:number,engagement:number,leads:number}>},workflow:{context:boolean,audience:boolean,references:number,drafts:number,review:number,scheduled:number,published:number}}.
Opportunity {id,title,topic,referenceIds:string[],segmentIds:string[],relevance:number,reasons:string[],evidence:Array<{referenceId,title,url?,source,observedAt?,detail}>,growth:{label:'observed'|'early_signal'|'insufficient',explanation:string},hypothesis:string,adaptation:string,confidence:'low'|'medium'|'high',suggestedFormat:'post'|'carousel'|'reel'|'video'|'newsletter',suggestedChannel:'linkedin'|'instagram'|'tiktok'|'youtube',isDemo:boolean}. Rank is editorial priority, never probability of success. Exclude demo refs from real insights; optionally return demo opportunities separately only when whole brand is demo (explicit isDemo). Do not synthesize YouTube custom performance scores, audience affinities or demographics from YouTube API. Native per-video metrics are observations only; match against brand-declared needs as editorial hypothesis. Do not merge platform metrics. Temporal topic comparison needs comparable observations; cold start stays insufficient.

GET /api/brands/:brandId/audience-signals → {signals:AudienceSignal[]}. POST same editor only {segmentId,topic,note,sourceUrl?,sampleSize?,sourceType:'public_content'|'editorial'} → AudienceSignal {id,segmentId,topic,note,sourceUrl?,sampleSize?,sourceType,createdAt}. Validate segment, bounds and URLs; source public claims need public URL. No personal names/emails/individual rows. DELETE /:id editor only.

POST /api/brands/:brandId/pieces/:pieceId/outcome editor only {publishedUrl?,publishedAt?,metrics:{views,engagement,leads},notes?} → Outcome {id,pieceId,segmentId?,title,publishedUrl?,publishedAt,metrics,notes?,origin:'manual',createdAt}. Only approved/scheduled/published pieces; explicit recording of publication, not external publishing. Upsert by pieceId; set piece status published with timestamp/url and actual manually supplied metrics. Preserve approval contract. Re-read latest piece after any await. Nonnegative finite metric bounds. Learning summarizes recorded outcomes without causal claims or auto-learning unsupported by data.

## Frontend agent: Journey.tsx, journey.css, journey-types.ts

Export Home, Opportunities, AudienceIntelligence, CompanyContext, Results. Use useWorkspace, api/json, existing UI. GET insights and context scoped to active brand; stale request guards. All loading/error/empty/reviewer states visible, no invented data or dead controls. Home next action based on progress + opportunities; Opportunities filters segment/search, expandable evidence and original draft action using existing POST /brands/:id/draft {referenceId,segmentId,format,channel,instructions}. Navigate studio on create, preserve created draft on refresh error. AudienceIntelligence wraps existing AudienceView (export from Brand.tsx) and adds signals/needs validation. CompanyContext shows source history + inline import, website/social/text and read/linked/failed/provided badges + existing BrandView. Results has inline selection of approved/scheduled/published piece, publication URL, metrics and notes; allows correcting existing outcome; learning table. Clear manual-metric origin. Existing calendar schedules and exports, does not auto-post.

Mode Operate. Inherit established green/light identity, no concept tournament/new visual world. No eyebrow labels, nested card grids, decorative charts or technical jargon in main flow. Comfortable type, accessible focus/labels, sensible mobile stacking. Agent must read impeccable craft-floor before UI edits. Root owns navigation/routes and CompanySetup; coordinate exported names and endpoint contract here. Don't edit root files.
