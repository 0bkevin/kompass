# Community questions using actual 30X business context

Verified 2026-10-18 through the native collaborative browser on isolated port 5502. The company context and proposed executive/IA and commercial audience groups came from the [real 30X source review](sources.json). **Every response in this test was submitted by the test agent to an explicitly labeled `[QA—respuestas simuladas]` question. There were zero real respondents.** This is functional verification, not evidence of 30X consumer preferences.

No AI request, external message, link distribution or publication was performed. The main user workspace was untouched. The local QA poll and its derived signals were deleted after testing; the two existing public-observation/editorial-hypothesis signals remained intact.

## Verification and observed infrastructure interruption

`node --test --test-timeout=20000 tests/community.test.mjs tests/interactive-audience.test.mjs` passed **12/12**. These existing automated tests cover roles and membership, creation bounds, aggregate counts, thresholding, pause/reopen, deletion, transient rate limiting and safe question-evidence links. [Test output](evidence/community/tests.txt).

A concurrent root build replaced the shared `dist` while this isolated production process retained an older SSR asset manifest. One public-page reload therefore requested missing old bundle hashes and remained at its loading state. Root confirmed the build timing. Restarting port 5502 against the new build restored the public form immediately, without changing any question counters or issuing another response. This was deployment sequencing, not a community-source defect; no community code change was required. Deployments must restart production hosts when replacing their build assets.

Deliberate 400, 409 and 404 responses are retained as negative-test evidence. No unexpected application exception was observed after the host restart. Both test tabs were closed and the isolated host was stopped after evidence collection.
