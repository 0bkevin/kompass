Reviewed: 2026-10-18. Scope: repository behavior inspected before compliance remediation in this turn. This records contractual requirements and implementation gaps; it is not a declaration that every use is lawful in every jurisdiction. No customer account, paid provider, or publication was exercised.

## Primary source findings

**Telegram.** Bot Developer Terms sections 4–4.5 require an accessible privacy policy, necessary retention, deletion procedures, encrypted user data at rest and credential protection. Section 4.3 rejects public-channel/group collection for AI products; the direct voluntary-submission exception requires informed individual, explicit, active and revocable consent. Section 5.2 forbids unsolicited spam and nonconsensual third-party media. These conditions are not satisfied merely by configuring a bot. [Official Bot Developer Terms](https://telegram.org/tos/bot-developers).

Telegram's Content Licensing terms cover AI deployment as well as training. Their consent exception is specific to the affected users, content and context; it does not transfer to other chats. The canonical page timed out during follow-up; Telegram's own locale URL was read successfully and exposed its English text. [Official Content Licensing terms](https://telegram.org/tos/content-licensing?setln=de).

The official Bot API documents HTTPS token authorization, `sendMessage`, and optional webhook secret-header authentication. Existing inbound code used a URL secret and chat match instead of that header. Secrets are encrypted by `server/db.mjs`; reference messages are ordinary SQLite JSON, without application-level encryption. Disk encryption was not established by this review. [Official Bot API](https://core.telegram.org/bots/api#sendmessage).

**Robots.** RFC 9309 says crawler rules do not grant access authorization. Respecting robots therefore supplements, and cannot replace, permission/terms review. No robots evaluator exists in the inspected generic fetch path. [RFC 9309, section 1](https://www.rfc-editor.org/rfc/rfc9309.html#section-1).

**Copyright.** Internet publication does not automatically remove copyright protection; permission and applicable exceptions depend on the work and use. U.S. guidance is illustrative rather than a worldwide legal determination. [U.S. Copyright Office digital-files FAQ](https://www.copyright.gov/help/faq/faq-digital.html).

**TechCrunch example.** RSS permits attributed, linked display with restrictions. [RSS terms](https://techcrunch.com/rss-terms-of-use/). General terms restrict automated extraction. [Terms of Service](https://techcrunch.com/terms-of-service/). Keep its seeded, paused feed unapproved for AI analysis without further permission review.

## Enforcement recommendations

1. Centralize source permissions by exact domain/path, intended use, evidence URL or written agreement, review date and expiry. Default unknown permission to linked-only or blocked. Separate access, AI processing, download, redistribution and publication rights.
2. Run the policy before network access in all entry points and on every redirect. Do not turn a UI checkbox, site ownership claim, successful HTTP status, absent robots rule or third-party scraper subscription into automatic permission.
3. Disable Telegram inbound before reading/storing/analyzing payload content. Keep outbound only through reviewed explicit publication. Reintroducing intake requires a separately designed consent, purpose, privacy, deletion and security flow that also satisfies the public-only challenge.
4. Keep community counts and company declarations independent from platform scraping. Minimize free text, identify hypothetical segments, and distinguish workspace identity data from research data.
5. Add server-side regression checks for disabled sources, redirect escape attempts and stale permissions. Preserve earlier imported records for review; do not silently delete customer work or label historical content compliant.

This review's code findings describe the pre-remediation state. Completion of an individual recommendation must be verified in the final implementation and tests; this document alone does not assert that a gate exists.
