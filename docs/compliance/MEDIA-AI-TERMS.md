# Media and AI provider terms review

Reviewed 2026-10-18 UTC against baseline commit `22faa7cf71af910ce7138c997dbf1a657d1c88df`. This report records the implementation before the compliance remediation in the working tree. It is a contractual and implementation review, not a blanket determination of legality in an unspecified jurisdiction. Only official primary sources were used; no credentials, paid API calls, account scraping, or publication were performed.

## YouTube discovery and trend metrics

**Implementation:** `server/social-providers.mjs` uses documented YouTube Data API v3 search, channel uploads playlists, and batched video details with API keys. It stores titles, descriptions, creator/channel identifiers, thumbnail URLs, duration, and raw view/like/comment counts. It does not retrieve viewer lists or comment bodies. Search results are locally reordered by views and assigned `officialRank`; that rank is produced by this application, not returned by YouTube. `server/intelligence.mjs` additionally calculates views/hour from historical observations, even though its YouTube composite score remains zero.

**Default contractual constraints:** YouTube Developer Policies III.E prohibit unauthorized audiovisual downloading and indirect scraping; III.E.4 generally disallow newly derived data/metrics. Public API data normally needs refresh or deletion within 30 days. The API client also needs its own accepted privacy policy, YouTube terms/Google privacy links, and source attribution. III.D requires the API project and credentials to identify this client without quota circumvention. Raw counts alone do not satisfy these other obligations. [YouTube Developer Policies](https://developers.google.com/youtube/terms/developer-policies)

**Important current exception:** Starting June 1, 2026, III.L provides a route for audited analytics developers with an explicitly accepted use case and policy amendment. The additional policy permits specified tagging, suitability analysis, scores, comparisons, and longer statistical storage. Eligible statistics and derived metrics can be retained for up to 36 months; text metadata still follows the ordinary 30-day rules. This is conditional permission, not an automatic entitlement of every API key holder. No acceptance or audit evidence was found for this deployment. The additional policy page was last updated September 14, 2026. [Additional derived metrics and storage policy](https://developers.google.com/youtube/terms/derived-metrics-policy)

**Other affected features:** Single-reference local/AI analysis derives topic/context relevance, saturation, adaptation, and a hypothesis from metadata; drafts can receive the entire YouTube reference. The opportunity AI endpoint already excludes YouTube references, but that does not guard the other analysis and drafting paths. There was no centralized 30-day expiry, stale-record cleanup, or documented accepted analytics grant at baseline.

**Enforcement:** Block YouTube collection and downstream analysis from YouTube-origin API fields by default in this editorial product. Do not label a calculated rank official. Before enabling a separately reviewed YouTube feature, record the approved API project, applicable analytics amendment/audit, permitted uses, metadata/statistics expiry, unavailable/deleted-video handling, deletion process, and public-facing policy acceptance. Preserve original source links and attribution in every view. YouTube's guide recommends applying for its compliance audit when a proposed use remains uncertain. [Developer policy compliance guide](https://developers.google.com/youtube/terms/developer-policies-guide)

YouTube provides branding appropriate for mixed-source interfaces; its icon/logo should identify the relevant content and link back to YouTube or an associated component. A platform label alone has not been reviewed as satisfying all branding requirements. [Branding Guidelines](https://developers.google.com/youtube/terms/branding-guidelines)

## Gemini video analysis

**Implementation:** `server/video-analysis.mjs` sends a normalized YouTube URL directly to Gemini's Interactions API. It does not download YouTube bytes. For Instagram/TikTok references from Apify it downloads the reported MP4 and uploads it through Gemini Files. A third route reads a brand's uploaded MP4 asset and also uploads it to Gemini. All paths add brand context/reference text, set `store:false`, and save the structured analysis locally. Uploaded Gemini files are deleted in `finally` on a best-effort basis; deletion failures are swallowed.

**Documented capability:** Google's video documentation explicitly supports direct URLs for public YouTube videos, excluding private and unlisted videos. The feature was documented as preview. This establishes a supported API input mechanism, not a license to reuse every third-party work or infer private audience characteristics. [Gemini video understanding](https://ai.google.dev/gemini-api/docs/video-understanding)

**Data handling:** Gemini's terms effective March 23, 2026 distinguish paid and unpaid service. Unpaid submissions and generated responses may improve Google products and undergo human review; sensitive, confidential, and personal information must not be submitted. Paid API service requires an active billing-linked project, does not use prompts/responses for product improvement, and can retain limited safety logs. EEA/Switzerland/UK client availability requires paid service. The service is for professional/business use, users must be 18+, and supported regions matter. `store:false` does not supersede those terms. [Gemini Additional Terms](https://ai.google.dev/gemini-api/terms)

**Rights:** Google's general API terms require the necessary rights to submitted material and do not transfer ownership of third-party content accessed via APIs. A public MP4 URL, an Apify result, or uploading a file is not independent evidence of those rights. [Google APIs Terms, §§3–5](https://developers.google.com/terms)

**Enforcement:** Disable every currently implemented video-analysis route until provider readiness and media/input rights have been reviewed. A future authorized own-media route should record rights to third-party music, footage, participants, and AI processing; keep personal data outside the challenge; select an appropriate paid provider project; disclose transfers and safety retention; and avoid unsupported private/unlisted URLs. The current Apify media route must not become an alternative to the collection restriction.

Gemini Files documentation states automatic file deletion after 48 hours and supports explicit deletion. That lifecycle does not prove deletion of every abuse-monitoring record or of this application's saved analysis. Persist deletion attempts and retry unresolved uploads rather than promising immediate universal erasure. [Gemini Files API](https://ai.google.dev/gemini-api/docs/files)

## OpenAI-compatible text analysis, drafts, and images

**Implementation:** `server/connectors.mjs` calls `/responses` with `store:false`, a schema, text context, and optionally an `input_image`. The default endpoint is OpenAI, but owners can configure any public HTTPS base URL. The analyzed reference and brand/segment material can be sent to that provider. The generator is inference only: no model training or fine-tuning workflow was found. No image generation API endpoint is implemented; uploaded images, remote thumbnails, and a local SVG demonstration asset must not be described as generated by an image model. The optional image parameter currently has no call site passing image input.

**OpenAI terms:** The business/API Services Agreement, effective January 1, 2026, allows integration into customer applications while requiring rights/licenses/permissions for inputs, respect for third-party rights, and evaluation of outputs. Input remains the customer's and output is assigned as between OpenAI and the customer, subject to applicable law; that does not clear underlying third-party rights. Customer content is not used to improve the services unless the customer explicitly agrees. [OpenAI Services Agreement, §§2–4](https://openai.com/policies/services-agreement/)

**Retention:** OpenAI documents default abuse-monitoring retention of up to 30 days, with exceptions and separately configured controls. `store:false` is not a promise of zero retention, and image/file safety-review exceptions exist. Custom compatible providers need their own review: OpenAI's promises do not govern an unrelated endpoint. [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data)

**Enforcement:** Apply a server-owned endpoint/provider policy before any outbound payload. Default to reviewed official providers; do not silently apply OpenAI claims to a custom endpoint. Require documented input rights and processing terms before enabling third-party contextual generation; exclude blocked-platform API data and media-derived analyses from every local and remote downstream path. Keep human approval and source provenance, and distinguish generation from factual validation.

## What this review does not establish

No deployed operator's Google billing status, regional eligibility, age policy, YouTube audit result, accepted provider contract, copyright licenses, or third-party media permissions were available. A user checkbox cannot establish a platform grant that the platform itself must issue. Official API access is a more appropriate collection mechanism than scraping, but compliance also depends on purpose, processing, storage, presentation, rights, and operating configuration. Whether a particular conduct is unlawful needs the jurisdiction and facts; contractual noncompliance and criminal illegality are different questions.

The conservative remediation for this delivery is to keep unverified remote collection/video paths blocked in server code while preserving reference links, editing, review, calendar, export, and company-owned editorial workflows. These are implementation controls and remaining prerequisites, not a claim that every deployment is legally certified.

Every current video input, including an uploaded asset, is blocked pending review. No browser field, provider key, own-account flag, or caller-supplied permission can override these blocks.

Those tests verify no outbound provider calls or spend reservations, unchanged reference records, released in-flight locks, and retained authentication/validation behavior. Offline mapping, URL/MP4 parsing, and atomic budget-ledger coverage remain. Previously successful provider-network scenarios were replaced with the expected policy rejections because those routes are deliberately unavailable. This scoped result does not replace the root agent's full-suite, build, and browser integration verification.
