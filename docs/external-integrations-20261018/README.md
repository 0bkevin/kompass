## Text provider implementation

`server/connectors.mjs` supports two transports under the existing server-side permission, HTTPS, SSRF, redirect and credential-isolation controls:

- Default/custom Responses-compatible endpoints use `/responses` with the existing request format.
- The exact official base `https://generativelanguage.googleapis.com/v1beta/openai` uses `/chat/completions` with a strict JSON schema, low reasoning effort for interactive use and completed-content checks. Other hosts do not inherit this behavior by matching a suffix.

The selected interactive model is `gemini-3.5-flash-lite`: the live nested-scene reel draft completed in 1.875 seconds. `gemini-3.8-flash` passed an initial smoke and analysis but exceeded the 60-second limit for drafts, including a low-reasoning retry; no incomplete drafts were saved. The legacy `gemini-2.5-flash-lite` appeared in the account's model listing but returned 404 for generation. Listing alone is not proof of usable quota. The initial [smoke result](gemini-smoke.json) records the earlier 3.8 probe; [app-level evidence](ai-live.json) records the final model and measured failures/recovery. These are finite samples, not a latency guarantee.

Google documents the [compatibility endpoint and structured responses](https://ai.google.dev/gemini-api/docs/openai). Its [pricing](https://ai.google.dev/gemini-api/docs/pricing) and [terms](https://ai.google.dev/gemini-api/terms) distinguish free and paid processing. Free submissions and responses may improve products and undergo human review, and must not contain sensitive, confidential or personal information. Professional use, adult users and supported-region requirements apply; API clients offered in the EEA, Switzerland or the UK require paid services.

The isolated test permission covers only original synthetic, non-confidential content. It is not a production review for arbitrary company uploads or private strategy. The operator explicitly chose “Free Gemini for public test content.” Localhost now uses `AI_DATA_MODE=public-test` and a short-lived review expiring 2026-10-25. The app identifies this mode before AI actions; workspace credentials do not inherit that label from the shared platform configuration. This is a processing constraint, not automatic detection or redaction of confidential content. No billing was enabled or purchased.

The adversarial review found an opportunity response that invented a past implementation despite valid JSON and a literal source citation. The request had demanded a sector case even when none was documented. The corrected instructions require unsupported examples to be explicitly hypothetical and conditional; the final live retry complied. A valid citation does not establish every generated claim. Editorial review and the visible evidence limits remain necessary.

Malformed reference-analysis fields now fail before overwriting an existing analysis, and provider timeouts return HTTP 504. The initial timeout observations below predate that status correction. The slower model's failures are retained in the evidence rather than counted as successful generation.

## Credentials

The dedicated key is held under an ignored private credentials directory with mode `0600`, inside a `0700` directory. Neither the key nor a working permission file is committed. Google OAuth credentials remain in the private ignored `.env`.

The main localhost database, uploads and encryption key were copied with the server stopped into the ignored private `data/localhost` directory. The original temporary directory was retained. `.env` now sets this durable local default, so plain `npm start` restores the same company, session and draft without temporary-directory launch arguments. The migrated session, company, edited draft and managed provider were verified through the running app. The secondary preview keeps its separate data directory.

An initial newly created key appeared in a setup diagnostic because Google returned a different key format than expected. It was deleted immediately; the key disappeared from the provider dashboard before its replacement was created. The replacement was downloaded directly into a private local file without returning its value in diagnostics. Only the replacement was used for the live tests.
