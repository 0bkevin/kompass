## Confirmed defect and scoped fix

At five responses, `server/community.mjs` records the question's same-origin public path in each derived signal. `SignalRow` in `src/features/Journey.tsx` passed that relative path to `safeExternalUrl`, which accepts absolute HTTP(S) URLs. This removed the evidence link while leaving the counts and question text intact.

Minimal reproduction: create a two-option community question, submit five voluntary responses for one group through the public UI, refresh audience signals, and inspect the derived card's links. Before the change, each community card had zero anchors despite valid API provenance. The ordinary public-content card retained its citation link.

Added `safeAudienceEvidenceUrl` in `src/lib/evidence-url.mjs` with its TypeScript declaration and used it only in `SignalRow`. It preserves existing absolute HTTP(S) citations and accepts only an exact generated `/community/` path with a 43-character safe token. Other internal routes, protocol-relative URLs, traversal/encoded paths, query/hash suffixes, executable schemes and malformed tokens are rejected. The global external-link policy was not changed. Count and sampling language were preserved.

`node --test tests/interactive-audience.test.mjs` was first observed red: the generated public question path returned `undefined` instead of the expected href. After the fix, all three tests passed, including the security rejection cases. `npx tsc --noEmit` passed. The running browser still uses the original compiled build because this agent was instructed not to build; root is coordinating the final compiled browser retest and after screenshot.

Public question and invitation tokens, credentials and cookies are intentionally omitted. The server and browser tabs remain available for the compiled retest.
