# Interactive review and approval audit — 2026-10-18

The independent browser/API audit is complete. Review, conflicts, role/company isolation, scheduling invalidation and published-history protection pass. One defect was found and fixed: API assignment changes could retain approved/scheduled status while changing the approval hash. Invalidation now compares the same normalized `pieceApprovalContent` definition used by `approvalVersion`, replacing the separate field list.

Normal production host: `npm start`, port `5466`, `DATA_DIR=/tmp/radar-interactive-approval-20261018`, discovery disabled. OpenAI, Gemini, YouTube and Apify credentials and `RADAR_API_ONLY` were unset. The existing production frontend build was used; no build or commit was performed. Only this isolated host was restarted after the server fix. Both companies retain zero enabled sources. No paid calls or external messages were required.

The owned synthetic Spanish fixture covers practical AI for LatAm EdTech CEOs improving commercial follow-up. Owner Ana, reviewer Rosa and editor Elena were registered/invited only in this isolated database; the owner also has a separate empty company. [Fixture IDs/content](evidence/approval/seed.json) exclude session cookies, which remain private in `/tmp/approval-seed.json`.

Native `preview_status` preceded fresh incognito `preview_open(open:false,reuseExistingTab:false,profileId:'incognito')` tabs. Every action targeted its returned tab ID. Owner/reviewer/editor used `127.0.2.66`, `127.0.2.166`, and `127.0.3.66` on 5466; at most two approval tabs were open. Desktop was 1440×1000 CSS px, mobile 390×844 CSS px. After the environment restart the earlier evidence was preserved and the main cycle repeated. Both approval tabs were closed at completion; the isolated host remains running.

The published piece and receipt were seeded directly into this isolated fixture database to test mutation protection without calling a connector. Its screenshot represents synthetic state; this audit does not claim real publication or external delivery coverage.

The fix is in [server/core.mjs](../../server/core.mjs). [tests/interactive-approval.test.mjs](../../tests/interactive-approval.test.mjs) adds six actual HTTP regressions for approved/scheduled rejection with unchanged storage, no-op assignment, explicit draft/review transitions, plan cancellation, stale approval rejection, fresh approval and scheduling. Before the fix, two cases failed (`200` instead of `409`). After the fix, `node --test tests/interactive-approval.test.mjs tests/remediation-calendar-1.test.mjs tests/core.test.mjs` passed 27/27.

[Native diagnostics](evidence/approval/21-native-diagnostics.json) separate the two intentional browser 409s and matching console resource errors from unexpected errors; unexpected browser failures were zero. API 403/404/409 assertions are recorded separately. [Post-fix browser diagnostics](evidence/approval/30-postfix-native-diagnostics.json) contain no new errors. [Final state](evidence/approval/29-final-state-after-fix.json) has the main piece approved with eight preserved comments, its assigned teammate, no active plan and both companies' sources disabled. No unresolved defect remains within this approval scope.
